# Using AI Knowledge Memory

Build instructions are in the [README](../README.md). Use a disposable Chrome profile for evaluation.


1. In a disposable Chrome 155+ profile, open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select this project's `dist` directory.
2. Open the extension through the toolbar, or its **Extension options** page. The library page also has **Open recall panel**.
3. In the full library's **Knowledge** destination, write a manual note and choose **Save note**. Close/reopen the library and find it through **Search saved Knowledge**. Empty search shows recent items. Use quotes for a contiguous phrase; enable **Broaden search (OR)** or **Include similar spellings** explicitly. Open **Filter Knowledge** for metadata filters. Arrow keys move through results; Enter opens the note in the detail workspace, with editing, sources, history and copy actions. The compact side panel offers recent results, excerpt copying, a reading view and an **Open note in full library** link. Archive results link to the selected capture and revision in the full library.
4. In **Settings → ChatGPT integration**, explicitly enable ChatGPT access. Use a synthetic conversation at an ordinary `/c/...` route; select text in a message and choose **Keep selection** to save, or **Preview selection** for an unsaved check. The right-click menu offers both actions. One live response's rendered structure has been inspected; enabled live saving, project routes and temporary-chat detection still need validation. Recognized temporary mode requires **Allow saving this conversation**; unrecognized mode is labeled unknown. Unsupported routes/layouts offer copy/manual paste, never broad capture. Failed menu delivery opens a local diagnostic.
5. On the enabled ChatGPT page, choose **Save loaded conversation**, review the message count, completion and warnings, then confirm the Archive capture. A timeout offers **Save partial now** or **Cancel capture**. After a lost reply, use **Retry same capture** to resume committed progress. Navigation stops the originating session; **Refresh Archive** recovers orphaned sessions as interrupted.
6. Choose **Archive** in the full library navigation (or **Search collection → Archive** in the side panel). Search uses the latest retained revision of every known message and standalone excerpt; **Include previous versions** exposes older revisions. Open a matching source to see exact ordered blocks, capture status and history. A capture does not add Knowledge notes.
7. Open a saved note to edit **My version** and use **Review and sources**. **Include outdated (superseded)** and **Include excluded notes** recover items hidden from default search. Open an Archive message's **Add this source to Knowledge** to append a quote to a named note.
8. Use **Preview selection → Review or replace before keeping** to exclude fragments or replace text before retention. After saving, placeholders in the note body do not erase original excerpts or history.
9. Use a note's permanent-removal control, an Archive conversation's deletion controls, or **Settings → Manage retained data → Cleanup and deletion**. Review the exact dependency counts and affected titles, then confirm. Confirmed deletion closes unsaved editors and clears search in every open extension view. **Delete all** also disables capture and removes old/staging libraries and caches; packaged extension files remain installed.
10. Choose **Settings → Backup and restore → Download backup** in the full library tab. Record counts and read-only recovery are under **Backup details and recovery**. Check your browser downloads and keep a verified copy outside this Chrome profile. Under **Export selected Knowledge as Markdown**, select notes; one downloads as `.md`, multiple as a ZIP. Markdown omits revision history and is not a restore format.
11. Expand **Restore a JSON backup**, then choose a canonical JSON backup. Validation checks format, hashes and relationships, then prepares a separate staging library. Review the replacement counts, save a current backup if needed, choose empty or replacement mode, acknowledge the loss of unsaved editors and confirm. Replacement disables capture and clears temporary allowances. Re-enable ChatGPT locally when needed. **Cancel preview / finish cleanup** removes an abandoned staging copy or retries old-library cleanup; it never rolls an activated library back.
12. Disable ChatGPT from **Settings** to stop integration and remove its optional permission.

The full library uses **Knowledge**, **Archive**, and **Settings** destinations with browser Back/Forward support. Links ending in `library.html?note={id}` or `library.html?capture={id}` open the intended detail directly. Switching destinations keeps unsaved editors and pending backup previews in this document; search workers are disposed and rebuilt when needed. If browser history requests another note while a draft is dirty, save or discard the draft before that note opens. Deletion and restore still clear every destination before proceeding.

Provisional shortcuts are **Alt+Shift+K** (recall) and **Alt+Shift+Y** (selection preview). Assign **Keep selected passage in Knowledge** yourself at `chrome://extensions/shortcuts`; it has no default shortcut. Operating-system and existing-extension collisions still need a manual check.

After rebuilding, reload the extension in `chrome://extensions` and reload the ChatGPT tab. Confirm Settings says **ChatGPT: Enabled** before expecting a floating button. Selecting response text does not itself grant access.

The extension requests `unlimitedStorage` alongside the permissions declared in its manifest. Notes, source excerpts, history and exports are unencrypted. Unsaved drafts and pending selections stay only in the open page; uncertain writes retain their exact retry intent there. Profile loss, uninstall and browser reset can destroy saved data: keep an external canonical backup. Checksums detect accidental corruption and do not authenticate a file. Immediate Undo is limited to an unchanged newly created selection and retains shared/independent Archive data. Permanent deletion cannot remove exports, clipboard history or OS backups, or guarantee forensic disk erasure.

The uncompressed JSON ceiling is **200 MiB**, not a capacity guarantee. Large imports materialize in memory and require disk space alongside the old generation. Small-file success does not establish capacity for complex large libraries. Run `npm run measure:a6` after building to measure the synthetic backup workflow on your machine.

## Recovery

For an interrupted restore before activation, reselect the backup after recovery. If cleanup reports retained copies, close blocking extension views, reopen one library tab, and use **Cancel preview / finish cleanup** or **Resume interrupted deletion**. For newer-schema failures, use **Read-only storage recovery** and keep the profile intact; do not uninstall to troubleshoot it. The recovery export is not a canonical backup and cannot be restored through the normal import flow.

## Switching development folders

Loading an unpacked extension from a different folder can give it a different extension identity and separate browser storage. Keep the old installation/profile until you have downloaded and verified a canonical backup. Load the new build in a disposable profile and restore explicitly; do not assume its library will appear automatically.
